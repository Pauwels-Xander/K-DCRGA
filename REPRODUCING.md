# Reproducing the thesis results

This document lists every result in the thesis and the exact run or analysis that
produced it. Set up the code and data first by following Sections 1–3 of
`[README.md](README.md)`. All commands are run from the repository root with the
package installed (`pip install -e .`). Sweep outputs land in `runs/<name>/seed_<N>/`;
the table and figure generators read those directories.

Seeds: every result, including the zero-shot study (RQ5), uses three seeds (0, 1, 2)
reported as mean ± standard deviation. Training is GPU-only; all scoring, aggregation, and
figure generation run on CPU.

---



## A. One-time data build


Where to obtain each raw input (public URLs, the MedDRA licence note, and the DrugCentral
dump) is listed in README §3.0 "Data sources at a glance"; the commands below assume those
inputs are already staged under `data/` and `third_party/`.

| Artifact                            | Command                                       | Output                             |
| ----------------------------------- | --------------------------------------------- | ---------------------------------- |
| KnowDDI graph + splits + baseline   | clone (README 3.1)                            | `third_party/knowddi/`             |
| Node features (MoLFormer + SapBERT) | `python experiments/build_node_embeddings.py` | `data/processed/node_features.pt`  |
| SE → MedDRA mapping                 | `python experiments/build_meddra_mapping.py`  | `data/processed/se_to_meddra.json` |
| MedDRA z_k initialisation           | `python experiments/build_zk_init.py`         | `data/processed/zk_init.pt`        |
| ATC injection data                  | `python experiments/build_atc_inject.py`      | ATC nodes/edges cache              |


The MedDRA steps need a licensed MedDRA distribution; the derived `se_to_meddra.json`
and `zk_init.pt` are bundled in the submission zip so they can be skipped.

## B. In-distribution results (RQ1-RQ5)



### RQ1: matched benchmark and component contrasts (Table "Matched in-distribution benchmark", Table "Operating-point metrics")

The five arms are trained under one matched protocol:

```bash
python experiments/sweep_bench.py --resume --all-seeds \
  --only decagon,kdcrga_v5,kdcrga_dedicom_v5,kdcrga_dedicom_v4,rgcn_mlp,lagat
python experiments/compile_results.py      # -> docs/results_rq1.tex (AUROC/AUPRC/AP@50)
python experiments/aggregate_prf.py        # -> operating-point precision/recall/F1 table
```

Arm-to-row mapping: `kdcrga_dedicom_v5` = K-DCRGA_DEDICOM (full model), `decagon` =
Decagon, `rgcn_mlp` = R-GCN+MLP, `kdcrga_dedicom_v4` = K-DCRGA_v4 (no ontology),
`kdcrga_v5` = K-DCRGA_MLP (view-MLP scorer). Outputs: `runs/bench/<arm>/seed_<N>/`.

### RQ2: long tail (per-frequency-quartile breakdown)

Produced from the same `runs/bench/` metrics (each `test_metrics.json` stores per-quartile
AUROC/AUPRC/AP@50):

```bash
python experiments/compile_results.py      # -> docs/results_rq2.tex
```



### RQ3: single-component ablation

The thesis reads the ablation off the RQ1 contrasts (each of the five arms differs by one
component), so RQ3 uses the **same** `runs/bench/` outputs as RQ1; the deltas and paired
Wilcoxon tests are emitted by `compile_results.py` (`docs/results_rq3.tex`,
`docs/results_rq1_wilcoxon.tex`).

### RQ4: what the attention learns (Table "Attention–MedDRA alignment")

Inference only, on the trained K-DCRGA_DEDICOM checkpoints (seeds 1 and 2; no retraining):

```bash
python experiments/sweep_rq4.py            # -> runs/rq4/<model>/seed_<n>/rq4_results.json
python experiments/aggregate_rq4.py        # -> the three-condition rho/JSD table
```

The three `z_k` conditions (trained / MedDRA-init / random) are swapped post-hoc on the
same frozen weights.

### RQ5: zero-shot to unseen side effects

```bash
for s in 0 1 2; do python experiments/sweep_rq5_zero_shot.py --seed $s; done
# -> runs/rq5/dedicom_v5/seed_{0,1,2}/{random,global_mean,meddra}/test_metrics.json
```

80/20 side-effect split (stratified by frequency); held-out-SE triples never enter
training; the three arms fill the held-out z_k / d_k rows by random draw, global mean, or
MedDRA ancestor average.

### Figures

TikZ figures (ontology injection, MedDRA init, architecture) are drawn in `thesis.tex`
and need no data. Data figures are generated by:

```bash
python experiments/make_figures.py         # -> docs/figures/
```



## C. State-of-the-art comparison and K-DCRGA + KnowDDI fusion

This is the comparison against KnowDDI on its own benchmark. It uses the canonical
pair-disjoint TWOSIDES split (no drug pair shared across train/valid/test) and one common
evaluator that scores every model on the identical test triples.

**1. Train the pair-disjoint arms** (3 seeds each; GPU):

```bash
python experiments/sweep_bench.py --resume --all-seeds \
  --only kdcrga_dedicom_v5_pd,decagon_pd,lagat_pd
# -> runs/bench/<arm>_pd/seed_<N>/best.pt
```

**2. Obtain KnowDDI predictions** on the BioSNAP test/valid sets, in KnowDDI's own
environment (PyTorch 1.6 / DGL 0.6; see README Section 1), using its dump script:

```bash
# in third_party/knowddi, KnowDDI env:
python pytorch/dump_predictions.py --seed <N>
# -> runs/fusion_pd/seed_<N>/knowddi_{test,valid}.npz
```

**3. Dump each full-graph model's Stream-F predictions** on the same triples (CPU, ~13 min/seed):

```python
from kdcrga.eval.dump_predictions import dump_stream_f
B = "third_party/knowddi/data/BioSNAP"
for kind, cfg in [("kdcrga_dedicom","kdcrga_dedicom_v5"),
                  ("decagon","decagon_pd"), ("lagat","lagat_pd")]:
    for s in (0, 1, 2):
        for split, txt, out in [("test","test.txt","f_test.pt"),
                                ("valid","valid.txt","f_val.pt")]:
            dump_stream_f(config_path=f"configs/bench/{cfg}.yaml",
                          checkpoint_path=f"runs/bench/{cfg if kind=='kdcrga_dedicom' else cfg}/seed_{s}/best.pt",
                          eval_txt=f"{B}/{txt}", out_path=f"runs/.../seed_{s}/{out}",
                          device="cpu", model_kind=kind)
```

(For K-DCRGA the checkpoint is `runs/bench/kdcrga_dedicom_v5_pd/seed_<s>/best.pt`; the dump
is split-agnostic. Outputs: `runs/fusion_pd/seed_<N>/f_{test,val}.pt` for K-DCRGA and
`runs/baseline_pd/<arm>/seed_<N>/f_test.pt` for the baselines.)

**4. Fuse and score** (CPU, seconds):

```bash
python -c "from experiments.sweep_fusion import run; run([0,1,2], runs_root='runs/fusion_pd')"
# prints per-seed and 3-seed K-DCRGA / KnowDDI / fused AUROC & AUPRC + the verdict,
# and writes runs/fusion_pd/aggregate.json
```

Each baseline's single-model number on the common evaluator is obtained with
`kdcrga.fusion.rescore.score_table` on its `f_test.pt`. The complementarity and zero-shot
fusion analyses are `experiments/fusion_complementarity.py` and
`experiments/fusion_zero_shot.py`.

## D. Runtime and hardware notes

- Baseline training (Decagon, LaGAT): ~1-2 h/seed on a 24 GB GPU.
- Full model / K-DCRGA_DEDICOM: longer per seed; the encoder runs once per pair and only
the light heads are recomputed per side effect, so cost is comparable to Decagon.
- KnowDDI: ~5-7 h/seed, and only on Turing/Volta-class GPUs (env constraint).
- All scoring, fusion, aggregation, and figures: CPU, minutes.



## E. The submission archive (TMS)

The reproducibility archive is built with:

```bash
python experiments/package_submission.py     # -> kdcrga_submission.zip (~90 MB)
```

It bundles the code (`src/`, `experiments/`, `configs/`, `tests/`), the documentation
(`README.md`, this file, `docs/thesis.tex`), the derived data artifacts
(`data/processed/node_features.pt`, `zk_init.pt`, `se_to_meddra.json`), the benchmark
splits (`third_party/knowddi/data/BioSNAP/`), and the recorded run metrics
(every `test_metrics`, `per_se_metrics`, `history`, `aggregate`, `rq4_results`, and
`fusion_metrics` JSON under `runs/`).

With the archive unpacked and the package installed, every thesis table and figure is
regenerated on CPU in seconds from the bundled metrics:

```bash
pip install -e .
python experiments/compile_results.py       # RQ1/RQ2/RQ3 tables + Wilcoxon
python experiments/aggregate_prf.py          # operating-point table
python experiments/aggregate_rq4.py          # RQ4 attention table
python experiments/make_figures.py           # figures
python -c "from experiments.sweep_fusion import run; run([0,1,2], runs_root='runs/fusion_pd')"
```

The trained checkpoints and prediction dumps (about 2 GB) are excluded for size;
re-running training (Sections B and C) regenerates them, or they are available from the
repository. The licensed raw MedDRA distribution is not included; the derived artifacts
above let the ontology arms reproduce without it. If the archive exceeds the TMS size
limit, `data/processed/node_features.pt` and the BioSNAP splits are the two large items
and can instead be rebuilt from Sections 3.1 and 3.2 of the README.
